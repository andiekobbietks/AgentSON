# Security Policy

## Supported versions

Security fixes are prioritised for the latest supported release. Until a formal support matrix is published, users should assume that only the latest release is actively assessed for security fixes.

## Reporting a vulnerability

**Please do not publish credentials, exploit details or personal data in a public issue.**

Use GitHub's private vulnerability reporting feature for this repository if it is enabled (repository **Security → Advisories → Report a vulnerability**). If private reporting is unavailable, contact the maintainer through the contact route on the [maintainer's GitHub profile](https://github.com/andiekobbietks) and request a private security-reporting channel before sending sensitive details.

Include, where safe:
- affected version, commit or deployment;
- impact and preconditions;
- a minimal reproduction or proof of concept;
- any suggested mitigation.

Do not include real AgentSON session exports, access tokens, API keys, health records or other personal data in a report unless the maintainer has arranged a secure transfer.

## Response expectations

The maintainer will acknowledge a report as soon as reasonably practicable, assess severity and affected versions, and coordinate a fix and disclosure with the reporter. These are intended process expectations, not a guaranteed service-level agreement. No fixed response-time commitment is claimed until the project has staffed security-response ownership.

## Scope

The report may concern the AgentSON format, readers, importers, CLI, platform modules, web interfaces, build/release process or published artefacts.
